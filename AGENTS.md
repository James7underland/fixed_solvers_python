# AGENTS.md

Правила для AI-правок в Python-порте `fixed_solvers`.

## 1) Базовые ограничения

- Язык: Python 3.10+.
- Численная семантика должна совпадать с C++-оригиналом `fixed_solvers-main`.
- Не менять кодировку файлов.
- Не использовать `from module import *` в реализации (в тестах — тоже избегать).
- Соблюдать SRP: не перегружать типы множеством ответственностей.

## 2) Структура проекта

- Публичный API экспортируется из `fixed_solvers/__init__.py`.
- При добавлении/удалении модулей обновлять `__init__.py` и при необходимости `pyproject.toml`.

## 3) Нейминг

- Snake_case для переменных, функций, enum и значений enum.
- Типы: snake_case + суффикс `_t`, как в C++-API (`fixed_system_t`, `fixed_solver_result_t`).
- Имена тестов — проверяемое поведение, с глагола (`test_returns...`, `test_throws...`, `test_solves...`).

## 4) Стиль кода и API

- Перед возвратом сложного значения вводить промежуточную переменную `result`.
- Передавать только нужные контейнеры/поля.
- Повторяющиеся блоки выносить в helper-функции.

## 5) Комментарии

- Для публичных функций — краткий docstring (`Args`/`Returns` при необходимости).
- Внутри функций — короткие комментарии только для нетривиальных мест.

## 6) Тесты

- В тестах явно выделять блоки `Arrange` / `Act` / `Assert`.
- Никогда не объединять Act и Assert в одном комментарии.
- Повторяющиеся длинные данные выносить в helper-функции/фикстуры.

## 7) Математика

- Для π использовать `math.pi`.
- Формулы (золотое сечение, Крамер, Виета/Кардано, trim ограничений) не «улучшать» без сверки с C++ и тестами.

## 8) Актуальность документации

- При изменении поведения кода обновлять `documents/*` и `README.md` по фактической реализации.
